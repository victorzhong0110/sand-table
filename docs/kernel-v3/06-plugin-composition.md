# DSH 插件组合契约

决策日期：2026-11-13。项目所有者确认以 Claude Whiteboards 的交互体验为参照，贯彻 DSH「一切皆插件」，优先复用已有能力。

本文件与 00–05 同为正式契约：规定 DSH 组合、插件边界及迁移目标；01–05 继续规定默认白板文档提供者内部的数据与事务。下面标注责任卡的接口是待实现目标，不是当前可调用 API。当前能力和证据等级见 [07](07-plugin-reuse.md)。

## 1. 产品与范围

Sand Table 是一套以白板为入口的 DSH 插件组合：个人在同一张地图观察、选择、讨论和操作资源；模型、Agent、网络、记忆、会话恢复及业务系统由各自提供者负责。白板可以跨仓库、Agent 会话与运行环境，不能限制为单一科研流程。

- 使用 DSH 的 profile/bundle、服务注入、生命周期、UI slots、工具注册与能力协商。不建第二个插件管理器、Agent 循环、通用网络客户端或聊天数据库。
- 默认提供者可以来自本仓库、官方包或第三方包；必装依赖由组合配置声明。默认安装不等于不可替换。
- 已有独立本地/MCP 白板继续可用；DSH 主路径迁移不删除现有作品，也不伪造独立模式的任务执行能力。
- 先复用原插件公开的服务、资源或扩展点。只有 UI 的插件不能被当作任意可嵌入组件；不导入其私有组件、不抓 DOM、不读写其内部数据库。缺少接口则做明确适配或上游扩展。
- 每个新能力先登记 07 的候选、版本、接口与验证结果，再写缺失部分。安装第三方包不等于通过组合验收。

## 2. 责任与权威

| 能力 | 提供者 | Sand Table 集成责任 |
|---|---|---|
| Agent、模型、工具执行 | DSH 插件组合 | 提供白板操作工具和资源上下文 |
| 会话记录、压缩、计量、检索 | DSH 对应插件 | 不复制日志；提供选区信息和资源读取 |
| 网络搜索/读取、浏览器、外部服务 | Web/连接器/MCP 等插件 | 将有来源的结果注册或引用为资源 |
| 图形文档、文件、表格、实验、服务器 | 对应资源提供者 | 预览、引用、操作入口和能力降级 |
| 白板原生对象、展示、关系、撤销 | 默认白板文档提供者，先复用 kernel | 保持现有事务、迁移、版本检查 |
| 工作台布局、选区、工具箱、主题 | 工作台/画布界面插件 | 提供一致交互，依赖服务契约 |
| 会话—白板—任务—产物关联 | 工作区绑定插件 | 宿主日志中的关联事实与可重建投影 |

每份内容只有一个权威提供者。DSH 日志是会话事实的权威；白板数据库是白板原生内容及引用布局的权威；图形正文仍可以由图形插件持有。外部内容预览是带版本的缓存，不成为第二个可写副本。

同一文档提供者内可以承诺原子事务及撤销。跨提供者操作逐项记录实际结果，只对声明支持的操作提供撤销或补偿，不能承诺撤销白板就撤销远程任务或 Git 提交。

## 3. 资源协议（T78）

以下名称是本项目待实现的协议，不冒充 DSH 已存在的 API。契约定义不依赖特定绘图库或 DSH 运行包；DSH 适配层通过已验证的服务注册机制暴露提供者。

```ts
type ResourceIdentity = {
  providerId: string;
  namespace: string;
  resourceId: string;
};
type ResourceRef = ResourceIdentity & {
  revision?: string;
  anchor?: string;
};
```

- 身份是三元组，均非空；providerId 最多 128 字符，namespace/resourceId 最多 512，revision 最多 256，anchor 最多 2048。标识按不透明字符串处理，不能直接拼文件路径或 URL。
- namespace 必须区分工作区或提供者实例；会话侧资源须包含提供者验证的生命周期身份，不能仅用可能复用的 sessionId。
- 未设 revision 表示读取当前版本；设定 revision 表示精确版本，不可用时返回 unavailable，禁止回退当前版本。编辑总是使用实际读取到的版本，即使引用跟随当前版本。
- T78 在 `ObjectSource` 增加可选 `resource: ResourceRef`，统一来源 Schema 和读写适配，作为资源绑定唯一来源。注册 `base.resource_reference` 作为默认引用对象，data 只保存本地说明，不存第二份 ResourceRef。外部正文不进入该 data。
- `source.external` 继续用于既有 ExternalLocator，不增加 kind=object/plugin，不把 ResourceRef 塞进 locator.uri。单个对象不能同时声明 resource 和 external 两个权威绑定；需表达多个来源时创建多个引用对象并建立关系。
- 跨资源语义关系依然连接本地引用对象；端点保持 objects.id，不直接把外部 ID 塞进关系端点或 data。多个展示可以共享同一个引用对象。
- 原生对象无需迁移成引用对象；旧库的 source.resource 缺省保持不存在。新增元 Schema、运行时校验、导出导入及旧数据兼容由 T78 一并实现；T76 不改变数据库版本。

提供者按能力实现 describe/read/open/subscribe/edit/export；只读提供者不要求 edit。read 返回资源引用、实际 revision、有界摘要及可用性；全文/附件按需读取。open 返回由宿主验证的路由或操作，不执行资源数据里的代码。状态至少区分 available/provider_missing/not_found/version_unavailable/unsupported/disconnected/forbidden，并给出可读原因。

编辑携带 operationId、expectedRevision 和提供者校验的操作参数。operationId 按提供者实例和资源划定作用域，同一 ID 的相同请求只能产生一次效果，异参重用明确拒绝。无持久幂等能力的提供者不得自动重试未知结果。默认白板适配不能把只用于连续历史合并的 intentId 误当去重机制。

提供者卸载只注销能力，不删除引用或作品；资源显示不可用，重装后按原身份恢复。订阅按工作区/资源/订阅代号清理，旧响应不能覆盖新工作区。

## 4. 上下文与空间语义（T80）

选区输入同时保存展示与对象两种身份：`presentationId + objectId + objectVersion + presentationVersion`，附 boardId/viewId 和提交时的布局、分组及关系摘要。同对象多个展示的正文可去重，布局不能去重。

- 发送时冻结选区；后续用户移动或切换白板不改变本次目标。缺失引用拒绝请求，不扩大为整板。
- 外部对象附 ResourceRef 和实际版本；提供者按权限制定读取范围。可读选区不自动授予写文件、执行任务或任意遍历的权限。
- 工作台只提供空间与资源语义；压缩、token 计量、会话检索复用现有插件。多种压缩策略由组合明确选定，不让两个提供者无约定地重写同一历史。
- 本轮新增的模型可见事实走 T77 验证的持久上下文接口；不能仅在易失消息投影中注入，以免恢复后模型看到另一份历史。
- 最多 200 个目标；关联扩展有界且返回 truncated/omitted 原因。全文按需读取，不默认把整板全部正文塞入每轮请求。
- 用户可以查看本次提供的对象、版本和省略项。展示记录不代表模型内部思维。

## 5. 会话绑定、恢复与产物（T79）

复用 DSH 的会话持久化、Session projection、控制接口及变更流；具体包版本和方法由 T77 的证据锁定。工作区绑定插件记录 workspaceId、boardId、session 身份、requestId、实际 turn、固定输入、输出引用和操作结果。关联事实进入宿主可持久记录，前端接收投影，不保存第二份权威聊天记录。

- 会话与白板允许多对多关联；不得把当前 UI 选中的 session 默认为全部白板的长期所有者。提交时明确绑定，之后不随导航改变。
- 普通 assistant 回复留在会话，不能自动变成白板便签。只有显式创作命令或已接入的结构化资源产物才触发作品写入。T76 已移除普通回复自动落板；现有 kind JSON 兼容通道在 T79 迁移后退出。
- 每种产物由提供者适配器声明识别方式、来源和资源引用；不靠扫描任意文本中的 JSON 猜测可执行作品。
- 产物接收与白板写入在 Host/服务侧执行，浏览器关闭不丢结果。写入在白板提供者内完成，操作与去重记录共享事务；提交后、回执前崩溃可以查证而不是重写。DSH 日志与白板库不假装构成分布式事务。
- 显示“执行完成”和“产物写入失败/待确认”两个维度；不能因 turn/end 就宣称作品已保存。只产生聊天回复的任务不要求创建作品。
- 状态只来自宿主证据。重连读取快照和后续事件；网络断开为状态未知，不把仍在运行的任务直接改为失败。不盲重发；取消请求需实际确认。
- 历史事件重放只计算状态，不再次执行工具或写作品。操作幂等验证与事件去重分开。
- 关闭浏览器、重启 Host、重启执行环境分别验收；恢复记录不承诺已终止的进程继续执行。

规则卡的 runs 是领域运行记录，不是第二个 DSH 调度器。T62 保留输入、参数、规则、请求/输出关联及作品写入状态；DSH 会话和执行状态由绑定服务读取/投影。本地存储需要的去重、租约只保护该领域提交与写入，不自行驱动模型轮次。T64/T65 复用此服务，不重新实现任务监听和聊天恢复。

## 6. 图形与界面组合（T54、T81）

先把外部绘图文档作为一个资源引用接入；现有 React Flow 仍可作为默认结构化画布。外部图形插件管理内部元素和正文，工作台管理它在总览中的位置。只有提供者提供稳定元素标识、编辑语义和版本后，才接元素级选区与跨图连线。

自由绘图的箭头不自动成为已确认语义关系；用户或明确操作才能建立依赖、包含、支持等关系。不能把图形转成静态图片就宣称支持共同编辑。

工作台经 DSH UI slots 注册面板、命令和视图；现有 iframe 桥只作迁移适配，不把插件页面嵌套视为已完成数据集成。DSH 原生代码插件、声明式数据包、受限作品代码视图是三种不同信任与生命周期边界；后两者不能借用前者的宿主权限。

## 7. 保存、分叉、导出与停用（T81、T82）

会话日志、资源文档和界面草稿分别恢复。DSH 会话分叉不等于复制外部资源。工作区组合导出新增独立入口与 manifest，列出引用、精确版本、提供者及随包资源；不改变 T25 原有白板导出格式的成功定义。

- 提供者可声明精确版本导出/导入或独立复制。分叉默认共享只读引用；要独立可编辑副本时调用复制能力并记录新身份，不能静默改共享原件。
- 依赖字节缺失、版本不可读或提供者不支持时，完整组合导出明确失败。用户可另选“仅引用清单”，结果写明未携带内容；不得自动降级并仍叫完整导出。
- T25 白板导出仍只包含白板数据、引用和其自身附件，说明外部资源未随包携带；不复制 DSH 聊天日志或安装凭据。
- 插件停用保留作品与引用；恢复安装不自动执行历史任务。工作区导入不安装或执行插件代码，不继承别处的信任授权。

## 8. 验收与交付顺序

1. T76：契约、复用清单、任务路由；普通回复不自动落板。
2. T77：固定真实 DSH 版本，验证加载、接口、生命周期与候选插件。没有版本证据，不使用滚动 master 文档代替目标运行包。
3. T78：资源契约、默认白板提供者、引用对象及不可用状态。
4. T79：宿主状态投影、关联持久化、服务侧产物接收和重连。
5. T80：包含空间与外部资源的选区上下文。
6. T54/T81：复用绘图能力并补齐资源关联、恢复与导出边界。
7. T82：可安装的组合、迁移及端到端验收；T66/T69 记录真实模型与真人使用。

最终场景：框选两个实验和一张图，要求 AI 比较并更新图形；执行中关闭页面，重开后看到正确会话、任务、图形版本及来源，无重复执行。随后分别测试 Host 重启、版本冲突、提供者停用/重装、共享引用与独立复制、完整组合导出失败和引用清单成功。脚本夹具只证明协议行为，真实插件组合与真实模型结果单独记录。
