## 为什么需要真机

DSH 插件的结构按官方源码核对过，但“装得上、入口出得来、Agent 调得到、任务能来回”这几件事只能在真实 DSH 里确认。T64（规则执行）依赖这次的结论。

## 准备

- 按 `workbench/dsh-plugin/README.md` 的安装说明操作。
- 记录：DSH 版本、操作系统、Sand Table 的提交号。

## 检查清单（每项记“通过 / 失败 / 未测”，失败附截图和报错原文）

1. 插件能用 `install_bundle` 装上，DSH 重启后不报错。
2. 左侧出现“新建 Sand Table”入口，位置在“新会话”下方、插件入口上方。
3. 点击后右侧主区域出现空白画布，没有重复的工作区列表或模型设置。
4. 在画布上建几个组件，关闭 DSH 再打开，内容还在。
5. 在普通会话里让 Agent“列出我的白板”“读一下某块白板”，Agent 实际调用了 Sand Table 的工具并给出正确内容。
6. 让 Agent 在白板上新建一个便签，画布上出现它，历史里标为 Agent。
7. 画布里出现白板内的任务入口（只有宿主声明能提交任务时才应出现）；提交一个任务，Agent 收到并能回写结果。
8. 断开或关闭插件时，白板内的任务入口消失或显示断开，不会留下发不出去的输入框。
