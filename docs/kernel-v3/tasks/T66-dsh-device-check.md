## 为什么需要真机

DSH 插件的结构按官方源码核对过，但“装得上、入口出得来、Agent 调得到、任务能来回”这几件事只能在真实 DSH 里确认。T64（规则执行）依赖这次的结论。

## 准备

- 安装固定的 DSH `0.2.2-rc.1` 和 Node `24.9.0` 以上版本。组合使用 `dsh-diagram@0.6.1-sand-table.1`，版本来源见 [T77 固定版本记录](../../adr/0008-dsh-provider-matrix.md) 和 [绘图复测记录](../07-plugin-reuse.md)。
- 下载当前 `main` 的 **DSH workbench bundle** Actions 制品 `sand-table-dsh-bundle`，解压后运行 `node install.mjs`。构建和安装细节见 [插件说明](../../../workbench/dsh-plugin/README.md)。
- 记录：DSH 版本、操作系统、Sand Table 的提交号。

## 检查清单（每项记“通过 / 失败 / 未测”，失败附截图和报错原文）

1. 按 T77 记录的固定版本和实际安装命令装入插件，DSH 重启后不报错；不假设旧的 `install_bundle` 方法仍存在。
2. 在组合配置声明的面板或侧栏位置出现 Sand Table 入口，按真实 slots 验证，不要求旧版固定排列。
3. 点击后右侧主区域出现空白画布，没有重复的工作区列表或模型设置。
4. 在画布上建几个组件，关闭 DSH 再打开，内容还在。
5. 在普通会话里让 Agent“列出我的白板”“读一下某块白板”，Agent 实际调用了 Sand Table 的工具并给出正确内容。
6. 让 Agent 在白板上新建一个便签，画布上出现它，历史里标为 Agent。
7. 画布里出现白板内的任务入口（只有宿主声明能提交任务时才应出现）；提交一个任务，Agent 收到并能回写结果。
8. 断开或关闭插件时，白板内的任务入口消失或显示断开，不会留下发不出去的输入框。
9. 普通 AI 回复只在会话；绘图插件的人工改动经 Agent 读取能得到实际新版本；来源可追溯。
10. 执行中关闭页面、Host 重启、提供者停用/重装分别检查；恢复原目标及状态，不重复任务或产物，不把未知状态猜成失败。
11. 框选两份实验证据和一张图，让真实 Agent 做比较并更新图稿。看到任务开始后关页再开，核对同一请求、原图版本、新图版本、两份输入和产物来源。用「组合文件」完整导出后导入到新工作空间，修改副本并核对原图。
