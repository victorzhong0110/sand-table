# T77 固定 DSH 版本与提供者实测

| 项 | 内容 |
|---|---|
| 执行 | grok |
| 依赖 | T76 |
| 分支 | `task/T77-dsh-provider-verification` |
| 类型 | 技术验证 |

## 目标

选择可运行的 DSH 精确版本，验证服务/客户端扩展、会话持久化、投影、上下文输入和候选插件，提供发布版本的真实接口证据。

## 先读

`AGENTS.md`、`05-delivery-contracts.md`、06、07、`workbench/dsh-plugin/`、T66。滚动网页仅作发现入口，API 以目标发布包/精确提交为准。

## 可改文件

- 新建 `docs/adr/0008-dsh-provider-matrix.md`、`workbench/spikes/dsh-providers/`，含固定版本依赖、lockfile、命令及去凭据样例。
- 07 的证据与状态、T66 的安装步骤和记录位置。
- 不修改用户现有 profile/凭据，不改产品依赖或放宽 engines；需适配时记录具体接口、文件和复测范围。

## 做法

1. 用隔离 home/profile 安装固定发布包，记录 Node/OS、包版本/完整性；检查 Sand Table 包是否自足，标明仓库相对 bridge 路径的问题。
2. 以最小插件验证服务注入、UI slots、session prompt/control、事件跟随、持久事件扩展及 projection；测试卸载/重装、冷读取、Host 重启，记录源码位置和样例。
3. 验证 Web 与默认计量/压缩提供者加载。无模型或凭据时实际请求/压缩单列未测，不在聊天中索取密钥。
4. 试装固定版本 dsh-context、dsh-diagram，区分“可打开面板”和“可共享资源”；核对分叉/导出。替代压缩和消息恢复在独立组合按需要评估。
5. 每项结论为直接复用/需适配/不采用/未测。无共同版本时记录最小适配方案与固定基线，不把需适配记为已通过。

## 验收

- 从干净目录重复安装启动真实 DSH，最小插件加载、公开接口调用、持久事件重启恢复通过。
- ADR 包含 07 要求的矩阵、命令/退出码、精确源码位置、失败原文与后续适配范围。
- fixture、真实模型、UI/人工观察分开；未测项标明阻塞卡，不用脚本替代 T66/T69。
- 运行 spike 固定命令及计划检查。
