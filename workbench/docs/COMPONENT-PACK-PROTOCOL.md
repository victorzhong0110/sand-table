# 组件包导入协议（Component Pack Protocol）

> **v2 协议。** v3 用数据包（`formatVersion: 2`）取代本协议，v1 清单导入时自动转换，见 [`docs/kernel-v3/03-types-and-extensions.md`](../../docs/kernel-v3/03-types-and-extensions.md) §6。

> 状态：v1 · 2026-10-20（已接入通用工作空间内核：板级撤销 + 随白板落盘恢复）
> 目标：让**别人能把自己要用的组件包**导入 Sand Table，用的组件与左侧栏里那些**同一种**。
> 配套实现：`core/packs.ts`（规范与校验）、`core/pack-fetch.ts`（防 SSRF 取件）、`server/packs.ts`（导入／导出工具）、`board/Toolbox.tsx`（左侧栏入口）。
> 集成契约：`docs/architecture/integration-2026-10.zh-CN.md` 决策 D3（校验入口唯一）与 D6（组件包进对象模型）。

---

## 0. 一句话

**组件包 = 一份自描述的 JSON 清单，里面是一组"组件类型 + 预填数据"的预设。**
导入它不会给程序装新代码，只是给左侧栏多出一组**可以一键放上画布的组件**。

---

## 0.1 本协议站在哪块地基上

本协议**不是新的一套组件契约**，而是仓库里既有两块约定的具体化：

1. **`docs/DEVELOPMENT_PLAN.zh-CN.md` §5.4「组件类型声明（内部）」**——组件类型在内部声明的东西（稳定类型标识、默认尺寸、可用呈现层级、支持的数据类型、可修改字段、无障碍名称、降级展示）。本协议对外暴露的字段，是这份内部契约的一个**子集**。
2. **同节那句硬约定**：「自定义分为配置、组合、代码扩展；代码扩展等第二个真实宿主出现再开放。**未知组件显示可理解的占位与说明，不静默丢弃**。」

由此得出本协议的三条边界：

| 允许 | 不允许 | 原因 |
|---|---|---|
| **配置**：预填 `data`，且这份 `data` 必须**通过与手写编辑完全相同的校验** | 塞进编辑器本身会拒绝的数据（超长、非法 URL、畸形结构） | 绕过校验的路径 = 一条后门 |
| **组合**：一组组件类型 + 预填内容 | **代码扩展**：新的渲染器、新的可执行逻辑 | §5.4 说代码扩展等第二个真实宿主；组件包必须是数据，不是代码 |
| 引用**本版本不认识的**组件类型（保留数据、占位展示、导入时给警告） | 静默丢弃不认识的部分 | §5.4 与 `board/ComponentRenderer.tsx` 的未知类型分支已经这么做了（"此版本不支持组件类型…；数据已保留"） |

**组件包不能**读仓库、写文件、改白板权限、跳过「人确认」那道闸——这些事根本不在协议的表达能力之内。

（对本项目自己的路线：§13「后续（未排期）」里列着"研究实验、基础设施运维、教学／知识、创作等领域包"。本协议是那件事的**第一步**：先有可导入的包格式，领域包的具体内容另议。）

---

## 0.2 三个层次，名字不要混

这三样东西都叫"包"，但**不是一回事**。文档与代码里提到"组件包"时，一律指本协议的**预设包**。

| 名字 | 是什么 | 边界 | 归属 |
|---|---|---|---|
| **预设包 / component pack**（**本协议**） | 一份 JSON 清单：给**已经存在**的组件类型配预设数据 | **纯数据**。不能加组件类型、不能带渲染器、不能带可执行逻辑、不能读写文件 | 本文件 + `core/packs.ts` |
| **领域包 / domain pack** | 一整块领域（代码领域、研究实验、基础设施运维……）的类型、组件、规则与工具 | 领域相关的能力**可以**扩展通用内核；与"只配预设"不是同一层 | issue **#13** |
| **DSH 插件** | 装在**宿主**（DeepSeek Harness 一类）里的界面插件，在宿主会话里注册视图 | 属于宿主侧，不进白板、不进通用内核、不进本协议 | issue **#18** |

写文档时的规矩：

- 说"组件包"＝本协议的预设包；要说另两层就明确写"领域包""宿主插件"。
- **不要**用"组件包"指领域扩展包——那会让"包能不能带代码"这条边界在文档里失效。
- 本文件只描述预设包；领域包与宿主插件的范围各自在对应 issue 里定。

## 1. 清单格式

### 1.1 顶层

```json
{
  "protocol": "sand-table/component-pack",
  "version": 1,
  "id": "com.example.research-kit",
  "name": "研究工具包",
  "description": "证据、比较与下一步检查",
  "author": "可选署名",
  "homepage": "https://example.com/research-kit",
  "components": [ ... ]
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `protocol` | ✅ | 必须**精确等于** `"sand-table/component-pack"`。这一条让"传错文件"变成一句清楚的「这不是组件包」，而不是一屏字段校验错误。 |
| `version` | ✅ | 整数，当前只接受 `1`。未知版本 → 明确报错，不猜。 |
| `id` | ✅ | 包的身份。`[a-z0-9][a-z0-9._-]{1,63}`，建议用反向域名（`com.example.research-kit`）。 |
| `name` | ✅ | 显示名，1–80 字符。 |
| `description` | | ≤ 400 字符。 |
| `author` | | ≤ 80 字符。 |
| `homepage` | | 必须通过 `safeUrl`（http/https）。 |
| `components` | ✅ | 1–50 条。 |

### 1.2 组件条目

```json
{
  "key": "evidence",
  "type": "reasoning",
  "title": "证据与未知项",
  "icon": "reasoning",
  "width": 320,
  "height": 220,
  "data": { "question": "这个结论的依据是什么？" }
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `key` | ✅ | 包内唯一，`[a-z0-9][a-z0-9._-]{0,63}`。**包内稳定标识**：同 `id` 再导入时按 `key` 对齐更新，而不是追加重复项。 |
| `type` | ✅ | 非空字符串，≤ 60 字符。本版本认识的类型按其规则渲染；**不认识的类型照样导入**，数据保留、在画布上以"此版本不支持该类型"的占位展示，并在导入结果里给出警告。 |
| `title` | ✅ | 1–120 字符（与 `sand_edit_space` 的 title 上限一致）。 |
| `icon` | | 必须是 `componentIcons` 里已有的图标名；**不认识时丢弃这个图标（回落到该类型的默认图标）并给一条警告**，不影响导入。 |
| `width` / `height` | | 缺省用该类型的默认尺寸；给了就夹在画布允许的范围内（宽 120–2000，高 70–1600，与 `sand_edit_space` 的 rect 校验同源）。 |
| `data` | | 预填内容。**一律走 `core/spaces.ts` 的 `checkComponentData(type, data)`**——类型已知时它按该类型的规则检查，类型未知时它只剩通用限制（整体 ≤ 40 KB、其中的链接字段必须是 http/https）。同一个函数、同一句报错，导入**不是**绕过校验的后门。 |

### 1.3 `data` 的两条补充规则

1. **省略即默认。** `data` 可以整个不写，这时用 `defaultData(type)`。
2. **只给合法子集。** `data` 里的键必须是该类型渲染器认识的键；未知键会被丢弃并记为一条警告（导入仍成功）。**类型未知时不丢键**：数据整体保留，交给渲染器本来就有的占位分支展示。

## 2. 导入

### 2.1 两条入口（同一个内核）

| 入口 | 用法 |
|---|---|
| **人**：左侧栏「组件」页 → 「导入组件包」 | 粘贴 JSON 文本，或填一个 `https://` 链接 |
| **Agent**：`sand_import_component_pack` | 传 `json`（原文）或 `url` |

### 2.2 工具签名

```ts
sand_import_component_pack({
  boardId: string,
  revision: number,
  viewId: string,
  author?: string,          // 默认 "human"
  intentId?: string,        // 意图分组键：同一次意图里的多次变更合成一步撤销
  source:
    | { json: string }      // 清单原文（≤ 256 KB）
    | { url: string }       // https 链接（服务端代取）
}) => {
  pack: { id, name, version, componentCount, source, importedAt, author },
  replaced: boolean,        // 同 id 再次导入 = 升级
  warnings: string[]        // 被丢弃的字段等
}
```

`sand_remove_component_pack` 同样接受可选的 `intentId`。

### 2.3 URL 取件的安全约束（`url` 入口）

代取 URL 是本项目第一条**主动出网**的路径，所以：

- 只允许 `https://`；
- 解析主机后**拒绝**回环 / 私有网段 / 链路本地地址（`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、`fc00::/7`），避免 SSRF 打到本机与内网；
- 跟随重定向时**每一跳都重新校验**；
- 5 秒超时，响应体上限 256 KB，`Content-Type` 必须是 JSON 家族；
- 取件失败 → 明确报「取不到 / 不是组件包」，不吞错。

### 2.4 导入语义

- **同 `id` 再导入 = 升级**：整包替换（按 `key` 对齐），旧包里的组件若在新包里不存在则被移除。
- **新 `id` = 新增**：左侧栏多出一个分组，标题是包的 `name`。
- 导入是**白板内容变更**：让 `revision` 递增，带 `author`，**进历史、可撤销、可重做**。
- 限额：每张板最多 20 个包；单包 50 个组件；清单 256 KB。

### 2.5 撤销与持久化：导入是白板级内容

导入与移除落在白板的 `componentPacks` 键上，**按键**记进撤销栈（不是抓整块白板）：

- 撤销一次导入**只**回退 `componentPacks` 这一键，不会连带回滚同时发生的别处改动；
- 撤销栈里的动作种类是白板内编辑（`import` / `remove`），不是外部效果——组件包是这块白板上的数据，白板撤销回退它是天经地义的事；
- 撤销之后包回到"导入前"的完整值，重做之后完整回来（预设一个不少）。

**导入的包随白板一起保存与恢复**：`componentPacks` 是白板落盘结构的一部分（`boards[0].componentPacks`）。重启、换浏览器、换 AI 客户端之后，导入的包仍在左侧栏里；它不是"进程内存里的临时物"。

### 2.6 移除与导出

- `sand_remove_component_pack({ boardId, revision, packId })` —— 移除一个包（同样可撤销）。
- `sand_export_component_pack({ boardId, packId })` —— 导出该包的清单 JSON（**原样可再导入**，这是"分享"闭环）。
- 左侧栏里每个包分组有一个「移除」入口。

## 3. 左侧栏表现

导入后，工具箱的「组件」页多出一个分组（组名 = 包名），组里的每一项是包里的一个预设：

- 标题用预设的 `title`，图标用预设的 `icon`（缺省用 `type` 的）；
- **点击** → 在画布上放一个该预设的组件（`data` 预填、`width/height` 生效）；
- **拖拽** → 与内置组件同一条通道（`application/x-sand-component`）；
- 预设**只影响新建**：已放上画布的组件不随包升级而变（避免"包一升，全板被动"）；
- 包名旁显示来源（`作者 · 来源地址` 或「粘贴的 JSON」），并提供「导出」「移除」。

### 3.1 放上画布 = 原生内容对象 + 绑定展示实例

预设被放到画布上时，产出的是**内容对象 + 绑定到它的展示实例**，**不是**一个自带内联 `data` 的实例：

- 预填数据进**原生内容对象**（`core/spaces.ts` 的 `nativeContentTypes` 与 `referenceContentTypes`），
  展示实例只保留**位置与呈现**，通过 `binding.objectId` 指回那个对象；
- 因此这份内容是**一等数据**：可以改名、可以被搜索、可以在别的白板上"再放一份"（内容共享、布局独立），
  也可以"复制出独立对象"（内容深拷贝、此后互不影响）；
- **类型未知**时没有内容对象可言（这个版本还不认识它），数据整体留在实例上，画布上以占位展示——
  和渲染器本来对未知类型的处理完全一致，不静默丢弃。

## 4. 与既有机制的关系

| 既有机制 | 组件包怎么对待它 |
|---|---|
| `checkComponentData(type, data)`（`core/spaces.ts` 的**唯一**校验入口） | **直接复用，且是唯一一处**。编辑器、手写编辑与组件包走**同一个函数**，不是两份看起来一样的代码。类型未知时也走它——它对未知类型只剩通用限制。 |
| `safeUrl(value)` | **直接复用**。 |
| 组件类型目录 `componentTypes` / `componentIcons` | **直接复用，不扩展**。包里可以引用本版本不存在的类型——那部分按 §5.4 的约定保留数据、以占位展示、并给出一条警告。 |
| `ComponentRenderer` 的未知类型分支 | **直接复用**。包里的未知类型落在同一个分支上，行为与"旧版本组件"完全一致。 |
| 不可信内容原则 | 组件包 = 数据，不是代码；不能读仓库、不能写文件。 |
| 源码写入的「人确认」闸 | 组件包**不在**协议的表达能力之内，天然绕不过也用不着绕。 |
| 历史 / 撤销 | 导入与移除都是**可撤销**的白板内容变更，按 `componentPacks` 键记录（见 §2.5）。 |
| 持久化（P1 工作空间） | 包是白板落盘结构的一部分，**随白板保存与恢复**（见 §2.5）。 |
| 对象与展示分离 | 预设放上画布产出**内容对象 + 绑定展示实例**，不是带内联 `data` 的实例（见 §3.1）。 |

## 5. 例子

最小可用清单：

```json
{
  "protocol": "sand-table/component-pack",
  "version": 1,
  "id": "com.example.review",
  "name": "评审包",
  "components": [
    { "key": "goal", "type": "task", "title": "目标与验收条件" },
    { "key": "unknown", "type": "reasoning", "title": "未知项",
      "data": { "question": "哪些还没确认？" } }
  ]
}
```

对应的命令（Agent 侧）：

```
sand_import_component_pack
  boardId=<id> revision=<n> viewId=<id>
  source={"json":"…上面的 JSON…"}
→ { pack: { id: "com.example.review", name: "评审包", componentCount: 2 },
    replaced: false, warnings: [] }
```

预填数据不合法时，报错**指到具体字段**（同一个 `checkComponentData`）：

```
组件「目标」的预填数据没有通过校验：Checklist values are invalid: items[1].done must be a boolean.
```

## 6. 后续版本可以加什么（本版**不做**）

- `version: 2`：`components[].layout`（一包多组件的成套模板，接近现在的「场景」）。
- 包签名 / 来源校验（当前只有"内容合法"，没有"来源可信"）。
- 包之间的依赖与继承。
- 领域包（#13）与宿主插件（#18）各有自己的范围，**不在本协议里扩**：见 §0.2。
