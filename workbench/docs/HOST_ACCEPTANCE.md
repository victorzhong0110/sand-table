# 真实宿主接入验证

状态：**待执行**。本地协议宿主及 CI 已验证；没有任何商业 AI 客户端在本项目中被记录为通过。此文准备可重复的接入步骤，不能当成完成记录。

## 先固定环境

记录待测客户端名称／版本、操作系统、模型名称、Sand Table 提交、Node 版本、外部仓库路径与提交，以及是否有未提交变化。客户端需能启动本地 stdio MCP；界面还需支持 MCP App 资源。仅远端 HTTP 连接的客户端不能直接使用当前交付，不把本地演示服务器暴露出去代替它。

在 `workbench/` 执行 `npm ci`、`npm run build`，再运行：

```bash
node --experimental-strip-types scripts/mcp-config.ts project=/absolute/path/to/external-repo
```

按待测客户端的实际设置导入生成的 `mcpServers` 配置。若它使用不同配置格式，仅转换字段结构，保留绝对 Node 路径、脚本路径和 workspace 参数；不在没有确认客户端版本的情况下承诺特定菜单或配置位置。

可再绑定另一个 worktree，检查总览跨工作区，而对象与活动分别映射。目录不能是 Sand Table 或 llm-research-os 产品本身。

## 第一段：连接与来源

在宿主中发出：

> 打开 Sand Table 总览。先确认 project 对应的工作区和 Git 版本，读取 README 与一个入口函数，说明当前索引没有覆盖哪些内容。暂时不要修改或执行仓库代码。

观察实际工具调用，不只看模型说“已连接”。记录 `sand_open_board` 的 boardId、workspaceId、HEAD、snapshot；`sand_read_source` 的文件、行号与 hash 应与本地内容对应。

界面出现时检查工具栏、卡片与详情；没有界面时，记录为“文字工具可用／界面未呈现”，不能判定 MCP App 通过。

## 第二段：共享关注范围与讲解

界面内选择一个对象，添加独特备注，例如“请优先解释这个输入的去向”。然后发出：

> 用 sand_read_context 读取我现在的选区和备注。解释这条功能路径的用途、输入、输出，读取相关源码后用 sand_publish_guide 放到板子。每步附对应源码引用和仍不确定的事情；没有执行就不要说已验证。

点击另一步，检查图中对象是否可见；再次要求 Agent 读取上下文，核对 guideFocus、步骤、对象与备注。测试从一个隐藏目标的筛选进入步骤。人工抽查解释是否受到引用支持；引用通过只说明内容匹配。

无界面宿主另外发出：

> 按我的请求，用 sand_focus 选中这条讲解的第二步，再用 sand_read_context 复述当前关注范围。

记录文本工具结果；不要借用开发网页的点击来冒充文字宿主独立完成。

## 第三段：活动、变更与生命周期

要求 Agent 在实际读取前通过 sand_report_activity 报告任务、实际 workspaceId 与对象，完成后报告 done。核对来源为自报，不称为操作系统监控；停止报告超过 60 秒后应显示最后已知。

在外部仓库的可丢弃副本中，由验收者手动改一处被引用文件但不提交；读取旧引用应报 changed。刷新后受影响讲解标为过期，Agent 必须重新读取才能更新。记录 HEAD 未变但内容 hash 变化；此处不要拿产品的只读能力当作宿主写入保证。

结束白板后，旧 ID 应不可读取；新开板不恢复之前的整理。关闭视图、断开 MCP 与进程退出分别记录：同一进程的板可在到期前继续存在，重启进程则丢失。不要把断线但未过期的活动说成正在运行。
