## 2. #12 已经落地、新架构应当**直接复用**而不是重写的四样东西

### 2.1 `core/history.ts`：撤销内核（对应 #11 §6.2）

#11 §6.2 写的是：

> 常规 Undo 连续撤回更早的有效编辑，Redo 恢复撤销；**不能让连续 Cmd+Z 在同一步的撤销与恢复之间来回震荡**。

**这一条已经实现了**（`core/history.ts`，游标模型）：

- `steps` 追加式写入链，每步存一份完整内容状态；
- `flips` 是撤销/重做/跳转的**日志**（不是弹栈）—— 撤销会往历史里再压一条「撤销了 X」，这条记录可被再次翻转，也出现在历史面板里；
- `cursor` 是当前位置；
- 同 token 的连续写入合并成一步（一次连续拖动 = 一步，一次连续输入 = 一步）；
- **只回退白板内容**（instances / spaces / links / groups / placements / packs / theme）。选中、相机、导航是视图状态，不进历史；**intent / proposal / validation 一律不碰** —— 回退不绕过人确认那道闸。

**对新架构的意义**：#11 要把「会话内历史」升级为「持久工作空间 + 审计日志」，并且要把**用户撤销栈**与**追加式审计记录**分开。这两样东西的上层（游标模型 + flips 日志）**已经存在**，要做的是**在上面加持久化**，不是换一套机制。

⚠️ **一处已知的字面分歧**（在 PR #12 描述里写明，等维护者拍板）：#9 第 6 条的字面要求是「撤销之后再按 Cmd+Z，被撤掉的会回来」，这与第 1 条「Cmd+Z 覆盖全部写操作」不能同时成立。本实现取第 1 条。若要改成严格照字面走，**只需动 `core/history.ts` 的 `applyFlip` 一处**。

### 2.2 组件包协议：`core/packs.ts` / `core/pack-fetch.ts` / `server/packs.ts`（对应 #11 §3.4）

这是 #11「领域扩展包」的**最小形态**，已经按纯数据实现：

- **包是数据，不是代码** —— 只能给**已存在的组件类型**配预设，**永远不能带来新的渲染器**；
- 未知类型：**数据保留**，画布上显示渲染器本来就有的占位，**不静默丢弃**；
- 预填数据走与编辑器**同一个**校验函数（`core/spaces.ts` 的 `checkComponentData`）—— 导入不是绕过校验的后门；
- 取件（`https://` 链接）只走 https，字面 IP 与**解析后**的地址都拒绝回环/私有/链路本地，**每一跳重定向重新校验**；
- 导入/移除是白板内容变更 → 进历史 → **可以撤销**。

**对新架构的意义**：领域包机制的**注册与分发**部分可以直接沿用这条链路（加类型、加组件、加规则），而**领域包不带代码**这条边界已经定死了。

⚠️ **命名冲突要处理**：#11 里的「领域扩展包」提供**类型、组件、规则和工具**；本仓库的「组件包」只提供**预设数据**。两者层级不同，名字相近。建议新架构侧改名（例如「领域包 / domain pack」与「预设包 / preset pack」），否则文档与代码里会长期混用。

### 2.3 `core/spaces.ts` 的 `checkComponentData`：统一校验入口

领域包注册新类型时，**复用这一个函数**，不要复制一份。它已经是编辑器与包导入共用的唯一入口。

### 2.4 `board/` 的交互基线（#9.1–#9.5，#11 §2.8 要求不重置）

- 边缘平移**默认关闭**（设置里可开）；
- 选中组件**直接可拖**（不需要先切编排模式；3px 位移阈值区分点击与拖动；拖固定组件会先解除固定，两写合并成一步）；
- **双击就地编辑**（Enter 提交 / Esc 取消 / 失焦提交；`board`、`space-link` 的双击仍是进入子白板）；
- **改完即存**（停止输入 600ms 自动提交、失焦提交、Esc 取消；**只回写改动过的键**并合并进服务端当前数据，不覆盖 Agent 在同组件其他字段的改动；一次编辑会话 = 一步历史）；
- **板级撤销/重做** + 历史面板（左侧工具箱「历史」页签）+ `Cmd/Ctrl+Z` / `Cmd/Ctrl+Shift+Z`；
- 材质区分组件、**完整界面／图标+标题／仅图标**三层展示。

⚠️ **一处与 #11 相关的既有约束**（在 #11 §11 里点到过）：位置锁定、视口锚定和层级置顶现在**共用同一个 pin 语义**，新架构里应当拆开，别沿用同一个字段。

## 3. 合并顺序与冲突面（要紧）

### 3.1 顺序（是事实与建议，不是硬性要求）

**事实**：#12 的 base 是 `feat/quiet-settings`（PR #5），所以它的 diff 只含本次改动；`main` 现在仍在 `fac509a`（#4 之后），#5 与 #12 都还没并入。

**建议的顺序**：**先合 #5 → 再合 #12 → 新架构以合并后的 main 为基线开分支。**

理由有三条，都是实打实的：

1. **#12 的结案说明已经写在 issue 上**（#6/#7/#9/#10 四条都写了「现象 → 根因 → 改动落点 → 怎么验 → 哪些没做到」）。拖久了，文档与代码会脱节。
2. **新架构要重构的文件，正是 #12 动过的文件** —— 基线越晚同步，**重叠越大**（见 3.2）。
3. **#12 的 CI 现在是绿的**（push 与 pull_request 两个事件都 pass）。等新架构的大改叠上去之后，CI 一红就很难判断是谁的问题。

**但时机与顺序由这一侧判断**：上面是事实摆出来之后的建议，不是硬性要求；什么时候合、先合哪个，**由新架构这一侧决定**。本仓库这边不代为合并，也不把顺序写成不可协商的前提。

### 3.2 冲突面（文件级，不是语义级）

#12 动过、而新架构几乎肯定要重构的文件：

```
workbench/core/model.ts        组件包类型 ComponentPack
workbench/core/store.ts        写入口 + 历史
workbench/core/spaces.ts       组件类型表 + 统一校验
workbench/core/results.ts      读回口径
workbench/core/history.ts      新增：撤销内核
workbench/server/spaces.ts     写入口 + 历史工具 + 读回
workbench/server/server.ts     工具注册
workbench/server/packs.ts      新增：组件包工具
workbench/board/*              画布、属性栏、工具箱、历史面板
workbench/local/*              本机接入与凭据
```

**好消息**：这些冲突是**文件级、可机械解决**的，**不是语义冲突** —— #12 不预设新模型，它是在现有模型上修 bug + 加一条纯数据协议。新架构重构这些文件时，#12 的改动大多可以**逐块迁移**而不是丢弃。

## 5. 本仓库里**没有**的东西（别假设存在）

- **没有持久化**：白板是**内存态**，进程退出即清空。#11 的 P1「独立于 Git 的持久工作空间」是**从零开始**。
- **没有多人协同**：人和 Agent 同一条历史，但并发写仍受原有的乐观并发闸约束（`Board changed`）。
- **没有插件市场 / 动态 SDK**：组件包协议刻意不引入第三方代码执行。
- **没有对象与展示实例的分离**（#11 §4.1）：现在「展示实例」与「对象」还是同一层，复制即复制、移除即删除。这是新架构的核心工作项。

## 6. 一次踩坑记录（省得再踩一遍）

- **`npm start` / 测试启动脚本的过期判断会漏**：它比较的是 `dist/host.js` 的时间戳与源文件目录里最新的时间戳，**只在源文件更新时重建**。手动改过 `workbench/local/*.ts` 或 `workbench/board/style.css` 之后，如果行为没变，先确认 `dist/` 是不是旧的 —— 跑一次 `npm run build` 再看。并发跑多个测试与手动构建会互相覆盖 `dist/`，**不要并发**。
- **实例在内存里持有 `dist/board.html` 与 `dist/host.js`**：重建之后**必须重启实例**，否则它还在发旧文件。
- **固定端口 + 重启 = 地址不变、凭据变**：这是「贴新链接进已开的标签页」这个场景的来源，`local/client.ts` 现在监听了 `hashchange` 来接住它。

## 7. 留给人拍板的三件事（我这边已经穷尽，不再往下推）

这三件不是"没做完"，是**已经走到我这边的边界**：要么是两条原始要求字面互斥，要么是归口要人定，要么是缺一份我拿不到的证据。写在这里是为了不用再靠口头转述。

### 7.1 #9 第 6 条与第 1 条字面互斥（等一个决定）

- **#9 第 1 条**："Cmd+Z 覆盖全部写操作"。
- **#9 第 6 条**："撤销后再按 Cmd+Z，被撤掉的会回来"。

这两条**不可能同时成立**：第 6 条要求"撤销"本身是一次可被撤销的操作，第 1 条要求 Cmd+Z 一直往回退。

- **本实现取第 1 条**：`applyFlip`（`core/history.ts:305`）里 `to = from - 1`，连按 Cmd+Z 会继续往回退，**不会**把刚才撤掉的那一步跳回来。依据是 #11 §6.2"不能让连续 Cmd+Z 在同一步震荡"——第 6 条的语义恰好会产生震荡。
- **要改成第 6 条的话，改动只在 `applyFlip` 一处**：在它里面判断"上一条 flip 是 undo 且其 `cursor` 等于当前游标"，是则把 `to` 取成 `from + 1`（等于 redo 回去），否则走原逻辑。不需要动 history 数据结构，也不需要动 UI。
- **目前状态**：未改。等一个明确的取舍。

### 7.2 `task` 组件的校验报错不读得懂（归口未定）

- **现象**：`core/spaces.ts:171` 只丢一句 `Checklist values are invalid.`，不说**哪一项**、**哪个字段**、**期望什么形状**。坏数据从 MCP 工具、从组件包导入走进来时，Agent 端拿到的是同一句话，只能自己回头猜。
- **影响面比看起来大**：组件包协议刻意让**预填数据走与编辑器同一个校验函数**（§2.3），所以这条坏消息同时出现在编辑、手写数据、导入包三条路径上。
- **建议改法（成本低）**：把校验拆成能带下标的形状，例如 `Checklist values are invalid: items[1].done must be boolean`。`checkComponentData` 已经是唯一入口，改它不影响别处。
- **我没做的原因**：这算"接口体验"还是"画布交互"、归 #6 还是 #9 没定，而新架构那边正在动同一片代码，我不先插一个没人认领的改动。

### 7.3 #10"放大"按钮消失：原始现象仍缺证据

> **集成轮已结**（2026-10-20）：项目所有者确认根因是「图标＋标题档的卡片层级切换按钮
> 被长标题推出卡片约 446px」，不是缩放条被盖住。本节的「等截图」要求作废。
