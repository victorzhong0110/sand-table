## 2. 接入是通的，"装一次就够"

按面板给出的 JSON 注册后：握手成功，列出 **34 个工具**。

**实例重启后客户端无需改配置即可自动跟随**——`local/session.ts` 的 `request()` 每次调用都重读会话文件。实测：实例重启后端口从 62317 变为 63663、token 全变，bridge 立刻跟上，`sand_list_boards` 直接可用。

> ⚠️ **前提**：MCP 配置里的 `--session-file` 与实例实际用的是**同一份文件**。用自定义 `--session-file` 启动实例时，配置不会自动跟着变——这正是 #6 问题 C 的成因。

**已落地**：面板「连接我的 AI」现在直接写明了这条前提（"装一次就够：工作台重启后客户端无需改配置即可自动跟随（前提是 MCP 配置里的 --session-file 与本实例用的是同一份文件）"）。

## 3. 多客户端共用一张板时的 revision 语义

- `sand_edit_space` 需要 `revision`；若期间浏览器端也改了这张板，会返回 `Board changed. Read current board and retry.`
- 本次踩法：Agent 侧"读 → 写 → 读回"如果跨多次独立连接，中途很容易被浏览器端顶掉。**在同一次 MCP 连接内完成读+写+读回**即可避开（本次即如此）。

**已落地**：

- 面板写明"浏览器与 MCP 客户端共享同一张板、同一份 revision 计数；Agent 侧的『读→写→读回』宜在同一次连接内完成"。
- #6 问题 B 另有修复：`sand_read_board` 增加 `instanceCount`、`sand_find_objects` 同时覆盖 objects 与 instances、写类工具返回新建/改动实例的 id 与标题（见 #6 的结案说明）。

## 4. 宿主侧的一个接入体验问题（非产品缺陷，但影响"装完就能用"的预期）

宿主在**会话进行中**注册 MCP 服务器后：运行时确实连上了（连接事件正常、工具清单里出现 34 个 `sand_*`），但**当次会话的工具目录没有刷新**，`mcp_invoke` 也不认这些名字——只有新会话才能直接调用。

- 期间用自写 stdio MCP 客户端兜住，功能完全一致（握手、列工具、调工具都正常）。
- 对产品侧的影响：README／面板说"装一次就能用"时，**"装"的时机会决定何时可用**。

**已落地**：面板注明"如果你的宿主是在会话进行中才注册 MCP，可能需要重开一次宿主会话才能看到新工具"。

## 5. 踩坑清单（已并入文档）

1. **会话文件里的 `url` 字段不含 `#session=` 片段**（token 是独立字段）——按它拼链接会静默丢凭据。与 #6 的问题 2 相同，此处从 AI 客户端侧再次确认。
2. **MCP 注册必须用绝对路径**：bridge 在 worktree 里，worktree 一删，配置就指向不存在的文件。
3. **会话文件在系统临时目录**（macOS `$TMPDIR`）：系统清理临时文件后需要重新 `npm start`。
4. **端口默认随机**，需要固定时用 `npm start -- --port <端口>`。

**已落地**：以上四条写进 [快速上手](QUICKSTART.md) 的「接入与排错」小节；`connection.json` 另加了一个**可直接使用的完整链接**字段（`url` 仍保持"origin + /"不变，避免破坏既有解析）。

## 6. 正面记录（可作为后续验收基线）

- 白板是**内存态**，进程退出即清空；已实测两次"重启即新空板"。
- 组件写入 → **浏览器画布实时出现**（经 MCP 创建的组件当场可见，无需刷新）。
- 顶层「总览」空间下可放组件，`sand_edit_space` 的 `create` / `place` 均可用。
- 34 个工具覆盖完整链路：读板（`sand_read_board` / `sand_read_context` / `sand_read_spaces`）、编排（`sand_edit_space` / `sand_edit_view`），以及"明确意图 → 具体提案版本与 digest → 人确认 → 宿主写入 → 实际内容及范围核对 → 绑定内容指纹的测试自报"这条改动链路（`sand_create_intent` → `sand_publish_proposal` → `sand_decide_proposal` → `sand_prepare_apply` → `sand_verify_proposal` → `sand_report_validation`）。
  ⚠️ 读组件实例以 `sand_read_spaces` 的 `instances` 为准（#6 问题 B 已修：`sand_find_objects` 现在也能查到）。
