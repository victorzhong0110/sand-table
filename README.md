# Sand Table

人和自己的 AI 共用的一张交互沙盘。打开就是一张空白板子，从左侧拖入组件，由你和自己的 AI 一起搭建、编排和理解。

白板是总览，可以跨越多个仓库与 Agent 工作区；工作区只是其中一部分。组件之间既有包含和从属，也有并列、依赖、比较和证据关系。你可以浏览详情、编排组件，或让自己的 Agent 维护白板。

## 直接开始

需要 **Node.js 22.18+**。搭建普通白板不需要仓库或 AI；需要 AI 时再连接你已有的本机 MCP 客户端。导入代码仓库时需要 Git，Python 符号索引另用系统 python3。

```bash
git clone https://github.com/victorzhong0110/sand-table.git
cd sand-table
npm start
```

首次启动安装本项目的固定版本依赖并构建界面。**默认不自动打开浏览器**（避免打断你正在做的事）——用终端打印的完整链接打开即可，想让它自动打开就加 `--open`。只索引目标仓库，不自动安装或运行目标项目。保持终端运行。

1. 打开后是一张空白板子。左侧“组件”按基础、数据、思考、开发分组；拖入画布或点击添加。
2. 选中组件后才出现属性面板。编辑内容、拖动、调大小、固定、复制、分组或添加关系；双击白板进入它。
3. “场景”提供可选的研究比较、Bug 修复和空白子白板，不会自动加载。
4. 要用 AI，点页面顶部“连接我的 AI”拿通用 MCP 配置，装进你已有的本机 MCP 客户端——
   AI 在你那边说话，它用沙盘工具在这里读写。只有宿主提供消息桥接（能真的发出去并收到回应）时，
   界面才出现直接对话入口；只有 MCP 时这里只显示接入状态与外部对话路径，
   不会给你一个发不出去的消息框，也不会让你复制提示词冒充“交给 AI”。
5. 要研究代码，再从左侧“仓库”主动导入本机 Git 路径。它成为当前空间中的一个子白板，按文件夹组织；不会把源文件铺满总画布。
6. 修改源码仍走明确意图、具体提案、审阅、确认、宿主写入和实际核对，不因普通编排自动修改。

**项目不提供模型服务，也不需要新的 API Key。** 普通浏览器聊天不会因本机安装 MCP 配置而自动连上；请使用同一台电脑上的 MCP 客户端。支持 MCP App 的宿主也可直接呈现这张界面。

## 已实现的工作流

- 工作空间落盘：默认 `~/.sand-table/workspaces`，原子写 + 备份回退 + 版本迁移；重启后作品仍在，不需要 Git。
- 原生内容一等公民：内容存在对象里，展示实例只管布局；同一对象可出现在多块白板上，内容共享、布局独立。
- 按意图分组的撤销／重做，外加只追加的审计日志；外部效果（已发布的改动、已运行的任务）不在白板撤销范围内。
- 一套历史：工具箱「历史」页签可看可跳，Cmd/Ctrl+Z 与撤销／重做按钮走同一套记录；人与 Agent 的记录一眼分得开。
- 板级内容（嵌套白板、分组、主题、组件包）同样可撤销：撤销一次组件包导入不会连带回滚你顺手改的主题。
- 自动保存：停止输入约 600ms 或失焦就提交；只提交你真正改动的字段，别人同时改的字段不会被你盖掉；
  同一字段被同时改动会明确报冲突并保留你的草稿。
- 组件包：数据型预设包（JSON 清单），只提供已有组件类型的预设，不能加类型、不能改代码；
  导入后可撤销、随白板一起保存，未知类型的数据保留并给提示。
- **多工作空间**：一台机器上可以并存多个工作空间，在「设置 → 工作空间」里新建、切换、重命名、删除；
  切换前会先把当前内容落盘，落盘失败就中止切换，不会出现「切换成功但内容没存上」。
- **跨进程文件锁**：同一工作空间同一时刻只有一个写者；本地服务与 MCP 客户端同时写不会互相覆盖，
  拿不到锁就明确报错，不是静默跳过。
- **撤销可以跳到任意一条记录**：历史是一棵分支时间线，撤销之后的新编辑会分出分支，
  旧分支仍然保留、仍然跳得回去——不再是「撤销一次就永远回不来的那条路」。
- **领域包**：类型、组件、关系、工具与模板来自注册表，内核不含领域语义；
  关闭全部领域包，通用内核仍能启动、建对象、编辑、保存、重开。
- 最多四个仓库或 worktree 共用总览；活动对应实际工作区，明确区分 Agent 自报与最近已知状态。
- JS / TS / JSX / TSX / Python / Markdown 源码索引；包含、导入和可能调用关系；分段读取、内容指纹、覆盖缺口与过期讲解。
- 嵌套白板、同一源码对象的多个独立实例、每个视图独立的选区和相机；拖动、缩放、框选、调整大小、固定与键盘操作。
- 18 种内置组件：源码引用、白板和入口、文本、标题、资源／媒体、代码片段、指标、状态、图表、表格、事件、任务、推理、比较、意图、提案、验证。
- Bug 修复与研究比较预设；手动表单或 Agent 配置组件；未知组件保留数据并显示占位。
- 黑白、温暖纸张与自定义颜色、字体、密度、圆角、减少动效；自定义正文对比度提示。
- 明确意图 → 实际文件基线 → 具体提案版本与摘要 → 人确认 → 宿主写入 → 实际内容及范围核对 → 绑定内容指纹的测试自报。

## 改动与生命周期

整理、连线和备注表达关注，**不自动授权修改文件**。确认绑定具体提案版本和 digest；提案替换、意图修订和实际内容变化需要重新检查。Sand Table 的源码服务器只读，写入由你的 Agent 客户端完成；检查与宿主写入之间并非原子操作，强制约束取决于宿主。测试报告会注明自报来源，不冒充服务器运行的测试。

**白板会保存。** 工作空间默认落在 `~/.sand-table/workspaces/<工作空间 ID>/workspace.json`，原子写入并保留上一份备份；
换浏览器、换 AI 客户端、重启进程都不会清空已保存的作品，也不需要 Git。`npm start -- --workspace-dir <目录> --workspace-id <ID>`
可以指定位置与工作空间。保存失败会显示出来，不会假装「已保存」。

**内容是一等数据。** 便签、图表、任务这些组件的内容存在对象里，不在卡片里：同一个对象可以同时出现在多块白板上，
改一处内容，所有展示一起更新；移动其中一处不影响另一处。「再放一份展示」和「复制出独立对象」是两件不同的事。
去掉 Git、源码索引和 AI 连接，白板仍然可以独立完成工作、保存成果。

撤销按你的意图分组：一次拖动、一次连续输入算一步，可以连续撤销与重做。审计记录与撤销栈是两回事——
它只追加，不影响撤销。已发布的改动、已运行的任务这类外部效果不在白板撤销范围内。
撤销之后的新编辑会分出一条分支，旧分支不会被丢弃，历史面板里仍能跳回去。

**AI 入口按真实能力显示。** 白板内的对话入口只在宿主**真的能接收任务并返回响应**时出现：
DSH 宿主插件接入后按结构化引用（对象 + 版本）发任务；只有 MCP 时这里只显示接入状态与外部对话路径。
宿主没接上、没声明能力或中途断开时，入口隐藏或显示断开状态——不会给你一个发不出去的消息框。
DSH 侧的插件包在 `workbench/dsh-plugin/`，集成契约见
[DSH 宿主集成契约](docs/architecture/dsh-integration.zh-CN.md)（**未在真实 DSH 实例中验证**）。

**领域语义不进内核。** 小说（人物／事件／章节）、科研（假设／证据／结论）这些词汇是领域包提供的：
类型、字段、校验规则、关系词汇与模板都在包里，内核只认注册表。
领域包提供的是**起点**，不强制流程——你完全可以从空白开始。

```bash
# 可选：提前连接仓库；画布仍然为空，之后从工具箱选择加入
npm start -- --workspace frontend=/absolute/frontend --workspace backend=/absolute/backend
npm start -- /absolute/repository          # 默认不自动打开浏览器
npm start -- /absolute/repository --open   # 启动后自动打开浏览器
# 可选：指定工作空间位置与 ID
npm start -- --workspace-dir /absolute/workspace-dir --workspace-id my-book
```

仅监听 127.0.0.1。启动链接含本机会话凭据，打开后从地址栏移除；请勿分享完整链接。会话文件里 `url` 是不含凭据的地址，`link` 是可直接粘贴的完整链接——程序拼链接请用 `link`。

## 验证与当前边界

```bash
cd workbench
npm ci
npm run build
npm test
```

外部集成使用固定版本的 lukeed/clsx 和 huggingface/huggingface_hub。完整改动测试在 clsx 的可丢弃副本中，由独立测试宿主写入并运行一个明确的源码断言；不会向外部仓库提交内容。

本地 Linux 启动、共享 MCP 会话、浏览器交互与改动链路有自动检查。**用户实际 Mac／MCP 客户端、真实模型讲解质量、初学者真人和受控对话对照仍需实际验收**；脚本通过不等于这些项目通过。当前没有公共组件代码执行 SDK、过程回放、多人协作或对外 Issue／PR 提交功能，这些属于规划中明确延后的范围。

**还没验证的**（如实列出，见 [problems.md](docs/problems.md)）：

- **DSH 插件包没在真实 DSH 实例里装过**：尚未完成真实 DSH 安装验证。插件的清单与槽位写法按官方源码核对过，
  但「装得上、入口出得来、Agent 调得到」三件事都还没在真机验过。
- 浏览器检查可本地运行；已有 Chromium 时可设置 `CHROMIUM_PATH`。新增 `test:host` 使用真实插件与本地服务，但 DSH 执行端是脚本夹具，不能替代真机模型验收。
- 真人验收（#15）尚未开始：没有真实被试、任务脚本与记录。
